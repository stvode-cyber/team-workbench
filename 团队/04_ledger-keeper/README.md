## 一句话简介

台账登记员专岗：三个时点（开工/动手前/收尾）自动登记，编号不重复、可随时回溯。

## 什么时候触发

- 每次任务要开工（自动触发，主 Agent 应该调）
- 动手改文件前（登记 IMP-xx 影响圈）
- 对话要收尾（登记 DC-xx 对话卡）
- 你说"记一下台账"、"登记"、"编个号"、"查查历史"

## 输出长啥样（示例）

**开工登记（REG-03）：**
```
### REG-03 — 2026-10-30 14:30
- 任务：重构用户模块鉴权逻辑
- 动机：现有 Session 方案扛不住并发，要换 JWT
- 边界：不动订单模块，不碰支付逻辑
- 负责人：AI
- 到期：本次会话
```

**动手前登记（IMP-02）：**
```
### IMP-02 — 2026-10-30 14:35
- 改动目标：src/lib/auth.ts 鉴权中间件
- 上游依赖：src/app/api/* 路由都用这个
- 下游影响：所有需要登录的接口
- 跨界：是（跨文件 + 跨模块）
- 回滚点：git commit 前的状态
```

**对话收尾（DC-20261030-01）：**
```
### DC-20261030-01 — 2026-10-30 16:00
- 对话主题：架构师 + 接手员联合摸了新项目家底
- 改文件清单：0
- 跑命令摘要：pnpm install ✅ / pnpm dev ✅ / pnpm test ❌
- 未走通的尝试：测试 2 个失败，原因是依赖版本不兼容，还没修
- 产出：REG-03 / IMP-02
- 遗留问题：测试失败，登记 GAP-01
```

## 常见问题

**Q：为什么要强制三个时点？**
A：铁律 #25——"只在聊天里说过没登记的 = 等于没发生过"。你以为 AI 记得上次干了啥，换个会话就全忘了。台账是跨会话接力的唯一依据。

**Q：编号规则是啥？**
A：REG 递增，IMP 递增，DC 带日期每天重开。SKILL.md 里有完整的编号前缀表（REG/IMP/DC/RCA/RT/FI/GAP/HDL/UPG/BLIND），每个有固定格式和递增规则。

**Q：台账写到哪个文件？**
A：默认写到工作目录根的 `工作流水.md`（DC 卡每次对话追加），项目根的 `CHANGELOG.md`（UPG 升级台账）。其他类型（REG/IMP/RCA）可以各自独立文件或统一文件——按项目规模来。

**Q：我手动改了文件但没登记 IMP，会怎样？**
A：台账登记员的硬性边界是不许跳过任何一个时点。改完再补也行，但要诚实登记"事后补登"。下回记得动手前先登记。
