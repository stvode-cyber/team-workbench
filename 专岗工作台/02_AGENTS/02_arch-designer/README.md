## 一句话简介

架构师专岗：新项目从零搭建 / 大重构时，按 01-03 三层出一份量身定制的架构设计卡。

## 什么时候触发

- 新项目还没开始搭，要搞技术选型
- 现有项目要大重构 / 技术栈迁移
- 你说"架构"、"设计"、"技术选型"、"拆分模块"、"画架构图"
- 不确定某块该独立成服务还是在现有模块里
- 依赖方向乱了，要理清楚

## 输出长啥样（示例）

```
═══ 架构设计卡 ═══
├─ 01 基础设施层：
│   ├─ 运行环境：Docker + Kubernetes — 微服务部署
│   ├─ 数据库：PostgreSQL 16 — 事务强一致需求
│   └─ 架构模式：事件驱动 — 团队有 5 人，熟悉 Kafka
├─ 02 平台层：
│   ├─ 核心框架：NestJS（后端）+ Next.js（前端）
│   ├─ 模块边界：{用户模块/订单模块/支付模块}，互不反向依赖
│   ├─ 依赖方向图：Application → Platform → Infrastructure ✅
│   └─ 反向依赖检测：✅ 无
├─ 03 应用层：
│   ├─ 数据模型 ER 图：{订单表/用户表/支付记录表}
│   ├─ API 规范：RESTful + 统一响应格式
│   └─ 错误码表：{参数错/鉴权错/冲突/内部错/资源不存在}
├─ 技术选型对比：A 保守 vs B 平衡 vs C 激进
├─ 架构风险点：{3 条，比如"Kafka 运维成本高"}
└─ 推荐：B 平衡方案，理由：{一句话}
```

## 常见问题

**Q：架构师和推演引擎啥关系？**
A：架构师出设计，推演引擎对这个设计做正推/反推/失败轨道。建议先用架构师搞出架构卡，再过推演引擎。

**Q：架构师会不会选很复杂的技术栈？**
A：不会。SKILL.md 里有技术选型检查清单，必须过"团队里有人会吗"、"有没有更简单的办法"这两关。

**Q：01-03 层是固定的吗？**
A：是。01 基础设施（全局选型）→ 02 平台层（模块边界+依赖方向）→ 03 应用层（数据+API+错误码）。每层有必答的硬约束。

**Q：只有新项目才用架构师？**
A：老项目大重构、技术栈迁移、模块边界理不清的时候也应该调。别等架构烂了才想起要治。
