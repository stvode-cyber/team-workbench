## RCA 五步（严格按顺序，不许跳步）

```
Step 1 现象（客观描述，不许主观判断）
→ 复现步骤：能复现才能分析，复现不了先想办法复现
→ 影响面：哪些模块 / 哪些用户 / 哪些数据
→ 严重程度：SEV1 紧急 / SEV2 高 / SEV3 中 / SEV4 低
→ ❌ 禁止用"可能"、"应该"、"好像"等模糊词

Step 2 复现（如果还没复现）
→ 真跑一遍触发路径
→ 抓日志 / 截图 / 录像
→ 写最短复现路径（Minimal Reproducible Example）
→ 复现不了 → 说明根因可能和环境/时序有关，要记录差异

Step 3 根因（5 Why 法 + 分类）
→ 连续问 5 次"为什么"，直到碰到结构性问题
→ 根因不许停在"人为错误"！必须回答"为什么这个错误能逃过去"
→ 根因分类：A 规则洞 / B 流程洞 / C 技术洞

Step 4 吸收（落点必须具体）
→ A 类（规则洞）→ 补规则：改 1号指令 / user_rules / AGENTS.md
→ B 类（流程洞）→ 加检查：加 hooks / 自动化脚本 / 门禁
→ C 类（技术洞）→ 找替代：写进技术债清单 / 找替代方案
→ 登记 GAP-xx（缺什么回流什么）

Step 5 回归测试（RT-xx）
→ 写显式测试用例覆盖 bug 触发条件
→ 这个测试不通过 = 不许合代码
→ 登记 RT-xx，每条 RCA 至少 1 条 RT
→ ❌ 没有 RT 的 RCA = 白做
```

## 5 Why 法使用规范

```
Why 1：为什么出 bug？→ {直接原因，比如"空指针"}
Why 2：为什么空指针？→ {上层原因，比如"没有做 null 检查"}
Why 3：为什么没做 null 检查？→ {设计层原因，比如"接口文档没说可能返回 null"}
Why 4：为什么接口文档没说？→ {流程层原因，比如"API 文档没人维护"}
Why 5（结构性）：为什么没人维护？→ {组织/架构层原因，比如"没有文档评审门禁"}
```

**关键**：Why 5 必须是结构性问题（规则/流程/架构），不许停在"这个人粗心"。

## 根因分类

| 分类 | 含义 | 吸收落点 |
|---|---|---|
| A 规则洞 | 没有规定不该做什么 | 改 AGENTS.md / 1号指令，补禁止项 |
| B 流程洞 | 规定了但没人检查 | 加 CI 门禁 / pre-commit hook / 自动化脚本 |
| C 技术洞 | 工具/库本身有缺陷 | 找替代 / 升级 / 绕过，写进技术债 |

**示例**：
- "开发忘了加 null 检查" → 表面是人为错误
- 深挖 → Why 3 发现是接口文档没写 → Why 4 发现文档没人审 → Why 5 发现没有文档门禁 → 这是 **B 流程洞**
- 吸收落点：加 CI 检查 API 文档覆盖率

## 根因分类 vs 常见误区

| 误区 | 正确做法 |
|---|---|
| "测试没覆盖到" | → 这是结果不是根因。Why 没覆盖到？因为测试没有自动生成？因为评审没要求？ |
| "部署时配置错了" | → Why 配置能错？为什么没有环境变量模板校验？ → B 流程洞 |
| "第三方库本身有 bug" | → Why 选了这个库？为什么没在 POC 里测出这个 bug？ → A 规则洞（选型前没 POC）|

## 输出模板：RCA 根因卡

```
═══ RCA 根因卡 ═══
├─ RCA-{序号}
├─ 症状（客观描述）：
│   ├─ 现象：{不带主观判断}
│   ├─ 复现步骤：{能真跑通的最短路径}
│   ├─ 影响面：{哪些模块/用户/数据}
│   └─ 严重程度：SEV1 / SEV2 / SEV3 / SEV4
├─ 时间线：
│   ├─ 时间点 1：事件（来源：日志/commit/反馈）
│   ├─ 时间点 2：事件
│   └─ 转折点：什么时候开始不对的
├─ 根因链（5 Why）：
│   Why 1：...
│   Why 2：...
│   Why 3：...
│   Why 4：...
│   Why 5（结构性）：...
├─ 根因分类：A 规则洞 / B 流程洞 / C 技术洞
├─ 吸收落点：
│   ├─ 改什么文件/规则：
│   ├─ 怎么改：
│   └─ 负责人/验证方式：
├─ GAP 回流：GAP-{序号}（哪些维度之前漏了）
├─ 回归测试：RT-{序号}
│   ├─ 测试路径：
│   ├─ 触发条件：
│   └─ 必须不通过才能说明修好了（红→绿）：✅ / ❌
└─ 验证方式（怎么确认真修好了）：
```

## 必查表

| 场景 | 必须问 |
|---|---|
| 出 bug 了 | 能复现吗？复现不了说明根因还没摸到 |
| 写根因 | 你是不是停在"人为错误"了？往下再挖 3 层 |
| 写吸收 | 这个改动之后，下次同样的错误能逃过去吗？ |
| 写回归测试 | 这个测试在 bug 没修之前能通过吗？（应该不能） |
| 关 RCA | RT-xx 写了吗？没写 = 不能关 |
