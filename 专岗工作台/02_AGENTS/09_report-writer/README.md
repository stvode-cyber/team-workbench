## 一句话简介

汇报出图员专岗：每次对话收尾出三层报告（状态盘 → 明细表 → 执行理解），四件套强制在头，树结构包代码块。

## 什么时候触发

- 每次对话要收尾 / 出汇总
- 里程碑完成 / 阶段性报告
- 你说"总结一下"、"出个汇报"、"进度"、"状态"
- 跨 AI 会话要交接（出 DC 卡）

## 常见问题

**Q：为什么必须有"执行理解汇总"？**
A：透明化。AI 理解的需求 vs 实际做的，可能有偏差——要么 AI 理解错了，要么用户没说清。这一块强制明示，让用户一眼看出"AI 到底有没有 get 到我要啥"。这是跨会话接力的关键。

**Q：四件套里的完成度百分比怎么估？**
A：要有依据，不许瞎编。比如 4 个子任务完成 2 个 → 50%。比如"架构师出卡 ✅ + 推演引擎过了 ✅ + 动手改代码 进行中 → 60%"。估算可以但要讲得出为什么。

**Q：格式铁律那么多，记不住怎么办？**
A：SKILL.md 里有自检清单——每次出报告前逐条过。核心几条：四件套在头、树结构包代码块、每行 40 字符、状态符号 5 种、独立板块套大单框、总结在尾。

**Q：DC 卡和汇报是什么关系？**
A：DC 卡是台账登记员的产物（每次对话收尾必出），汇报是汇报出图员的产物。两者可以合并——汇报收尾时自然带出 DC 卡格式。实际上主 Agent 对话要结束时，通常先调台账登记员写 DC-xx，再调汇报出图员出三层报告。
