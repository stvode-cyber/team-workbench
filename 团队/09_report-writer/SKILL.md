# 汇报出图员 · 专属知识手册

## 铁律原文（必引用）

铁律 #11：动手前给组合逻辑图（汇报也一样——四件套在头，先看状态再看细节）
铁律 #25：只在聊天里说过没登记的 = 等于没发生过（汇报必须带台账编号）

## 三层报告模板

### 第一层：状态盘（一眼看清全局）

```
═══ 四件套 ═══
台账 REG-{xxx}（✅ 进行中 / ✅ 完成）｜ 时间轴 YYYY-MM-DD ｜ 编号 {类型}-{序号} ｜ 完成度：XX%
```

**四件套强制要素**：
1. 台账编号 + 状态（✓ 进行中 / ✓ 完成 / ✗ 阻塞）
2. 时间轴（YYYY-MM-DD）
3. 自身编号（DC-xx / REG-xx / IMP-xx 等）
4. 完成度百分比（估算值，但不许瞎编）

### 第二层：明细表（话题级汇总）

```
═══ 话题级汇总 ═══
├─ 要点 1：{一句话}
├─ 要点 2：{一句话}
├─ 要点 3：{一句话}
└─ 一句话结论：{这轮到底干成了啥}
```

### 第三层：执行理解（透明化 AI 的理解和偏差）

```
═══ 执行理解汇总 ═══
┌─ 你原始需求：{用户原话或精炼}
├─ 我理解的意图：{AI 认为用户想要什么}
├─ 我实际做了什么：{客观描述，不带主观评价}
└─ 偏差汇报：{理解和实际做的差距，没有偏差就写"无偏差"}
```

### 附加层：接下来要做（驱动下一步）

```
═══ 接下来要做 ═══
┌─ AI 自己能干：
│ ├─ {任务 1，一句话}
│ └─ {任务 2}
└─ 等你拍板：
   ├─ {需要用户决策的 1}
   └─ {需要用户决策的 2}
```

### 附加层：项目总进度（有项目时必出）

```
═══ 项目总进度 ═══
├─ 里程碑 1 [x] 100%
├─ 里程碑 2 [>] 60%
│   ├─ 子任务 A [x] 100%
│   ├─ 子任务 B [>] 80%
│   └─ 子任务 C [ ] 0%
└─ 里程碑 3 [ ] 0%
```

### 收尾：总结（必须在最后）

```
═══ 总结 ═══
✅ 干成了 / ❌ 没成 / ⚠️ 有问题等你拍板 —— 一句话总结
```

## 格式铁律（必须遵守，自检用）

| 规则 | 要求 |
|---|---|
| 全简体中文 | 代码/命令/路径/技术标识符除外，首次括注 |
| 树结构符号 | ├── │ └──（用中文的，不是英文） |
| 树结构包在代码块里 | 整个 ``` ... ``` 包裹 |
| 每行硬限 40 字符 | 超出主动硬换行 |
| 状态符号只用 5 种 | `[ ]` 未开始 / `[>]` 进行中 / `[x]` 已完成 / `[!]` 阻塞 / `[-]` 已归档 |
| 独立板块套大单框 | 执行理解汇总 / 方案框 / 接下来要做 / 总结 套 ┌┐└┘ |
| 不许加模块间分隔线 | ❌ "─ —" 这种分隔线不许有 |
| 不许整个汇报套大外框 | 每个板块独立，外面不再套一层 |
| 不许用旧格式竖排 | ①②③④ 这种数字竖排不许用，改用树结构 |
| 四件套必须在最开头 | 上来先看状态 |
| 总结必须在最末尾 | 收尾一句话 |
| 不许编造进度 | 没跑通就写没跑通，不许自欺欺人 |

## DC 卡格式（对话收尾必出）

```
═══ DC-{YYYYMMDD}-{序号} ═══
├─ 对话主题：{一句话}
├─ 改文件：
│   ├─ {路径 1} — {改了啥}
│   └─ {路径 2} — {改了啥}
├─ 跑命令：
│   ├─ {命令 1} → ✅ / ❌ + 关键输出
│   └─ {命令 2} → ...
├─ 未走通的尝试（必须写！）：
│   └─ {尝试} → {为什么没走通}
├─ 产出：REG-xx / IMP-xx / RCA-xx / RT-xx ...
└─ 遗留问题：{还没解决的}
```

## 输出规范检查清单（每次出报告前自检）

```
自检清单：
[ ] 四件套在最开头
[ ] 台账编号写了吗？
[ ] 时间轴有了吗？
[ ] 完成度百分比写了吗？
[ ] 所有树结构包在 ``` 代码块里
[ ] 独立板块套大单框（执行理解/接下来要做/总结）
[ ] 每行不超 40 字符
[ ] 状态符号用对了（[ ] / [>] / [x] / [!] / [-]）
[ ] 总结在最末尾 + 状态 emoji
[ ] 全简体中文（技术标识符除外）
[ ] 没编造进度（没跑通就写没跑通）
[ ] 执行理解汇总没漏（AI 理解 vs 实际执行的偏差明示）
```

## 常见错误

| 错误 | 正确做法 |
|---|---|
| 状态 emoji 错了（把 ✅ 写成 ✗） | 自检时对照：完成=✅ / 没成=❌ / 等拍板=⚠️ |
| 用英文括号 `()` 套独立板块 | 必须用中文的 ┌┐└┘ |
| 用数字 1. 2. 3. 竖排 | 改用树结构 ├─ │ └─ |
| 整个报告套了个大外框 | 每个板块独立，不许嵌套 |
| 没写"执行理解汇总" | 这个是强制的，AI 理解和实际做的偏差必须明示 |
| 写了"大概 80%"这种模糊话 | 估算可以，但要有依据：已完成 4/5 个子任务 → 80% |

## 必查表

| 场景 | 必须问 |
|---|---|
| 出汇报 | 四件套写在最开头了吗？ |
| 写进度 | 这个百分比有依据吗？还是瞎编的？ |
| 收尾 | 执行理解汇总写了吗？偏差明示了吗？ |
| 跨会话交接 | DC 卡写了吗？未走通的尝试记录了吗？ |
