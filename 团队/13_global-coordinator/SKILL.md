# 总负责人专属知识

## 一、新项目初始化六步 SOP（必按序执行）

```
Step 1  确认项目身份
        ├─ 项目名（中文名，展示用）
        ├─ 项目代号（英文，文件命名用，比如 greenrhino）
        ├─ 技术栈（从用户说的或 package.json 推断）
        └─ 核心目标（这个项目最终要干啥）

Step 2  创建项目负责人
        ├─ 从 {工作台}\团队\12_project-pm-template\agent.md 复制
        ├─ 替换四个占位符：
        │   {项目名}     → GreenRhino 安全浏览器
        │   {项目代号}   → greenrhino
        │   {技术栈}     → Tauri + React + TypeScript
        │   {核心目标}   → 安全浏览、防追踪、隐私保护
        └─ 写入 {项目根}\.trae\agents\{项目代号}-pm.md

Step 3  推送接手员摸底
        ├─ 调 project-taker → 扫目录、跑构建、查 git
        └─ 输出：项目画像卡

Step 4  推送架构师 + 推演引擎
        ├─ 架构师出 01-03 层架构卡
        └─ 推演引擎过一遍（新项目也有风险！）

Step 5  建基线文件
        ├─ {项目根}\AGENTS.md（或调 agents-builder 自动生成）
        ├─ {项目根}\项目进程.md（v0.1）
        │   ┌─────────────────────────────────┐
        │   │ # GreenRhino 安全浏览器 v0.1       │
        │   │                                   │
        │   │ ## 目标                           │
        │   │ 安全浏览、防追踪、隐私保护         │
        │   │                                   │
        │   │ ## 里程碑                         │
        │   │ - [ ] M1 架构搭建                 │
        │   │ - [ ] M2 核心功能                 │
        │   │ - [ ] M3 联调上线                 │
        │   │                                   │
        │   │ ## 当前状态                       │
        │   │ 刚初始化，等待接手员摸底           │
        │   │                                   │
        │   │ ## 负责人                         │
        │   │ greenrhino-pm                     │
        │   └─────────────────────────────────┘
        └─ 初始化台账 REG-001

Step 6  交付给用户
        ├─ 汇报初始化完成
        ├─ 列出已就位的专岗
        └─ 等用户点头后推进下一步
```

## 二、项目负责人生成要点

### 项目代号规则

- 全小写英文，连字符分隔
- 2-4 个单词以内
- 不超过 20 字符
- 避免通用词（不用 project、app、my）

✅ 好的：greenrhino、safe-browser、input-method
❌ 坏的：project1、my-app、test

### 占位符替换（pm-template → 项目专属）

模板里的占位符必须全部替换：

| 占位符 | 替换为 | 示例 |
| ------ | ------ | ---- |
| `{项目名}` | 项目中文名 | GreenRhino 安全浏览器 |
| `{项目代号}` | 项目英文代号 | greenrhino |
| `{技术栈}` | 技术栈描述 | Tauri + React + TypeScript |
| `{核心目标}` | 一句话目标 | 安全浏览、防追踪、隐私保护 |

### 存放位置

```
{项目根}\.trae\agents\{项目代号}-pm.md
```

注意：这是**项目级**的，装在 `{项目根}\.trae\agents\` 下，
不是全域的 `%userprofile%\.trae-cn\agents\`。
每个项目一个，互不干扰。

## 三、方向把控判断标准

### 什么时候需要做方向把控

- 用户连续两次说"帮我看看这个项目"（可能隐含方向问题）
- 台账显示最近 5 次改动中有 ≥ 3 次返工
- 里程碑逾期 ≥ 1 倍时间
- 架构师或推演引擎报告了"方向可能有问题"

### 方向判断四问

1. **目标变了吗？**（核心目标是否还是当初的那个？）
2. **方法偏了吗？**（技术栈/实现方式是否偏离了架构师定的方向？）
3. **资源够吗？**（当前剩余时间/能力/工具能不能完成剩余里程碑？）
4. **值不值得？**（按当前投入产出比，要不要继续？）

### 判断结果

| 四问结果 | 判断 | 动作 |
| -------- | ---- | ---- |
| 全 ✅ | 方向正常 | 继续推进，台账登记 |
| 1 个 ⚠️ | 轻微偏离 | 推演引擎过一遍，微调 |
| 2 个 ⚠️ | 明显偏离 | 竞品调研员 + 架构师重新评估 |
| ≥ 3 个 ⚠️ | 方向错误 | 暂停，出方向校正方案等用户拍板 |

## 四、汇报节奏模板

## 五、和其他 Agent 的边界

```
总负责人（global-coordinator）
│
├── 管启动 / 接手 / 方向把控 / 定期汇报
├── 创建项目负责人（{项目名}-pm.md）
└── 推给 01-12 号通用专岗干活（自己不写代码）

项目负责人（{项目名}-pm.md）
│
├── 管这个项目每天的具体推进
├── 跟进里程碑
├── 调 01-12 号通用专岗
└── 更新《项目进程.md》和台账

接手员（project-taker）
│
├── 一次性摸底（新接手时）
├── 扫目录 / 跑构建 / 查 git
└── 出项目画像后退出

三者关系：
总负责人 → 创建 → 项目负责人 → 持续跟进 → 推进项目
总负责人 → 触发 → 接手员 → 一次性摸底 → 退出
```

- [ ] 台账 REG-001 已登记

- [ ] 已读《项目进程.md》最新版本
