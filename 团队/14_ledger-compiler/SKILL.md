# 跟单员专属知识（主动型 v2）

## 一、三层工作模式（从被动到主动）

```
对话计数 0-4  ──→  轻量模式
                    ├─ 跟上记录：写 1-3 条压缩摘要进 CHANGELOG.md
                    ├─ 检查有没有新阻塞/风险 → 追加到问题卡
                    └─ 不编译索引卡（还没到周期）

对话计数 5 ──→  编译模式
                ├─ 强制走完整六步编译 SOP
                ├─ 生成/更新 .trae/index-card.md（版本号 +1）
                ├─ 对话计数重置或继续累计（按项目负责人决定）
                └─ 问题卡完全重算（不是只追加）

对话计数 5+（继续）──→  继续轻量模式，等下一个 5
```

## 二、日常对话跟上记录（轻量模式 SOP）

```
每次对话收尾时：

Step 1  回顾对话内容
        ├─ 用户说了什么核心请求
        ├─ AI 做了什么核心操作
        ├─ 有没有新阻塞/风险冒出来
        └─ 有没有完成的里程碑/子任务

Step 2  写压缩摘要进 CHANGELOG.md
        ├─ 1-3 条（根据对话长度）
        ├─ 每条 ≤ 15 字（硬限）
        ├─ 每条带编号（REG-xxx / IMP-xxx / DC-xxx）
        ├─ 编号按 CHANGELOG.md 里最大的 +1
        └─ 状态标记：[ ] / [>] / [x] / [!]

Step 3  问题卡检查
        ├─ 读 .trae/index-card.md（如果存在）
        ├─ 对话里有没有新的阻塞（[!] / RCA- / 卡住等）
        │   ├─ 有 → 追加到 CHANGELOG.md + 索引卡 🚧 版块
        │   └─ 没有 → 跳过
        ├─ 对话里有没有新的风险（推演报 / 安全扫 / 隐患）
        │   ├─ 有 → 追加到 CHANGELOG.md + 索引卡 ⚠️ 版块
        │   └─ 没有 → 跳过
        └─ 对话里有没有解决了的阻塞
            ├─ 有 → 把旧 [!] 改成 [x]，新摘要说明"解决了"
            └─ 没有 → 跳过

Step 4  对话计数 +1
        ├─ 读 .trae\dialog-count.txt
        ├─ +1 写回
        ├─ 判断 %5 == 0？
        │   ├─ 是 → 触发完整编译（下面第三部分）
        │   └─ 否 → 本轮结束
        └─ 本轮结束
```

## 三、完整编译 SOP（每 5 次对话触发 · 严格按序）

```
Step 1  读全量台账
        ├─ 先找所有台账文件
        │   Get-ChildItem {项目根} -Recurse -Include *CHANGELOG*, *台账*, *ledger* -File
        ├─ 读 CHANGELOG.md（如果存在）
        ├─ 读项目进程.md（如果存在）
        ├─ 读 .trae\agents\{代号}-pm.md 的里程碑
        └─ 读 DC-xx 对话卡（如果存在）
        ⚠️ 来源确认：确保不丢也不重复

Step 2  台账归类到六大版块
        每条台账判断属于哪个版块：
        │
        ├─ 🎯 里程碑 → 包含"M1/M2/M3"、"架构"、"搭建"关键词的
        ├─ 📋 待办   → 状态 [ ] 或 [>] 的
        ├─ 🚧 阻塞   → 状态 [!] 或含 "RCA-" 的
        ├─ ✅ 已完成 → 状态 [x] 的
        ├─ ⚠️ 风险   → 含 DZ- / 推演 / 安全 / 风险 的
        └─ 📌 下一个 → 从 📋 待办里挑优先级最高的 1-3 条

Step 3  每条写摘要（≤ 15 字）
        规则：
        ├─ 动词开头（加/改/修/建/删/完成）
        ├─ 名词结尾（什么东西）
        ├─ 不写时间、不写作者、不写无意义修饰
        └─ 末尾必须标台账编号（REG-015 / DC-003）
        ✅ 好摘要：加 SQL 索引检查 Hook → REG-015
        ❌ 坏摘要：2026-10-31 AI 帮用户完成了 SQL 索引的检查 Hook 的添加

Step 4  每个版块截取最近 N 条
        ├─ 🎯 里程碑：全显示（通常 ≤ 10 条）
        ├─ 📋 待办：最近 5 条
        ├─ 🚧 阻塞：全显示（阻塞不能漏）
        ├─ ✅ 已完成：最近 10 条
        ├─ ⚠️ 风险：全显示（风险不能漏）
        └─ 📌 下一个：3 条

Step 5  生成索引卡
        ├─ 输出位置：{项目根}\.trae\index-card.md
        ├─ 或者：{项目根}\.trae\agents\{代号}-pm.md 末尾追加
        ├─ 更新时间：每次编译更新"最后更新"字段
        └─ 版本号：每次编译 +1

Step 6  登记台账
        ├─ 自己也写一条台账：REG-{next} 索引卡编译 v{N}
        └─ 调 ledger-keeper 登记
```

## 二、六大版块判断标准（速查表）

| 版块 | 判断关键词 | 状态标记 | 举例 |
| ---- | ---------- | -------- | ---- |
| 🎯 里程碑 | M1/M2/M3/里程碑/架构搭建/核心功能/联调上线 | 看项目进程.md | "M2 核心功能 60%" |
| 📋 待办 | 做/待/未/计划/准备 | `[ ]` `[>]` | "加 SQL 索引检查 Hook → REG-015" |
| 🚧 阻塞 | 阻塞/卡住/RCA-/排查/等拍板/issue open | `[!]` | "测试环境 SQLite 版本不兼容 → RCA-003" |
| ✅ 已完成 | 完成/搞定/合入/提交/上线/修复 | `[x]` | "M1 架构搭建完成 → REG-003" |
| ⚠️ 风险 | 风险/推演报/安全/漏洞/可能/隐患 | 无固定标记 | "推演引擎报 SSR 冲突 → DZ-007" |
| 📌 下一个 | 从 📋 里挑优先级最高 | 无标记 | 阻塞优先 → 然后待办 |

## 三、摘要写法规则

### 格式模板
```
{动词} {对象} {补充（可选）} → {台账编号}
```

### 动词库（固定用这些，别自造）

| 动词 | 适用场景 |
| ---- | -------- |
| 加 | 新增功能 / 新增文件 / 新增配置 |
| 改 | 修改已有功能 / 修改代码 |
| 修 | 修 bug |
| 建 | 新建架构 / 新项目 |
| 删 | 删除文件 / 删除配置 |
| 完成 | 完成里程碑 / 完成任务 |
| 查 | 调研 / 搜索 / RCA 分析 |
| 补 | 补测试 / 补文档 / 补缺失 |
| 优化 | 性能 / 代码 / 架构 |
| 阻塞 | 卡住不能推进（🚧 版块专用） |

### 摘要长度硬限

- **硬性上限：15 个汉字字符**（不含台账编号）
- 超过必须压缩
- 压缩顺序：先删修饰词 → 再删补充信息 → 再把长词换短词

### 好 / 坏例子

| 原始台账 | ✅ 好摘要（≤ 15 字） | ❌ 坏摘要（超过 15 字或啰嗦） |
| -------- | ------------------- | ------------------------------ |
| REG-015：2026-10-31 在项目 backend 目录下新增了 SQL 索引检查 Hook，用于在 PR 合入前扫描所有 SQL 语句的索引命中情况 | 加 SQL 索引检查 Hook → REG-015 | 在 backend 目录下新增 SQL 索引检查 Hook 用于扫描索引命中 |
| REG-003：2026-10-30 完成了 M1 架构搭建的所有工作，包括目录结构设计、模块边界定义和技术选型 | M1 架构搭建完成 → REG-003 | 完成 M1 架构搭建所有工作包括目录结构模块边界技术选型 |
| RCA-003：测试环境 SQLite 版本 3.42.0 和代码期望的 3.45.0 不兼容，导致数据库初始化失败 | [!] SQLite 版本不兼容 → RCA-003 | 测试环境 SQLite 3.42.0 和代码期望的 3.45.0 不兼容导致数据库初始化失败 |

## 四、索引卡格式规范

### 文件头
```
═══ {项目名} · 索引卡 v{N} ═══
├─ 项目代号：{code}
├─ 当前阶段：M{X} {名称} [{状态符号}]
├─ 最后更新：YYYY-MM-DD HH:mm
└─ 总台账数：N 条
```

### 版块格式
```
├─ 🎯 里程碑进度
│   ├─ M1 架构搭建 ██████████░ 90% → REG-003
│   ├─ M2 核心功能 ██████░░░░ 60% → 进行中
│   └─ M3 联调上线 ░░░░░░░░░░  0% → 未启动
```

### 进度条生成
- 总长度固定 10 格
- 实心 █ 表示已完成，空心 ░ 表示未完成
- 计算：进度 % ÷ 10 = 实心格数
- 例：60% → ██████░░░░（6 实心 + 4 空心）

### 下一个目标选择算法
1. **🚧 阻塞**优先解（RCA-xx 条目）
2. 然后**📋 待办**里优先级最高的（按台账编号先后）
3. 最多选 3 条
4. 每条开头加序号 1. 2. 3.

## 五、按需下钻机制

### 索引卡里的台账编号怎么来

每条台账写的时候就必须带编号：
```
REG-{next} = Register（登记）编号
IMP-{next} = Implementation（实施）编号  
DC-{next}  = Dialog Card（对话卡）编号
RCA-{next} = Root Cause Analysis 编号
DZ-{next}  = Drize（推演）编号
```

### 下钻命令（AI 直接跑）

```powershell
# 按编号定位原台账
Select-String "REG-015" CHANGELOG.md

# 如果 CHANGELOG.md 不存在，从各分散文件搜
Get-ChildItem . -Recurse -File | Select-String "REG-015"
```

### 下钻流程
```
AI 读索引卡 → 看到"加 SQL 索引检查 Hook → REG-015"
↓
AI 执行：Select-String "REG-015" CHANGELOG.md
↓
拿到完整台账条目（做了什么、为什么、影响范围）
↓
继续干活
```

## 六、编译频率建议

| 场景 | 编译频率 | 触发者 |
| ---- | -------- | ------ |
| 新项目初始化 | 1 次（第一版索引卡） | 13_global-coordinator |
| 日常对话 | 每 5-10 轮编译 1 次 | 总负责人 / 登记员 |
| 台账超过 50 条 | **必须**编译 | 任何 Agent 触发 |
| 指南针校准 | 1 次（先读索引卡） | 13_global-coordinator |
| 接手项目 | 1 次（从接手员画像编译） | 接手员之后自动 |

- [ ] 确认台账编号无重复

### 编译后检查清单
- [ ] 六大版块全覆盖
- [ ] 每条摘要 ≤ 15 字
- [ ] 每条都标台账编号
- [ ] 里程碑进度条正确
- [ ] 🚧 阻塞和 ⚠️ 风险全显示（不截断）

- [ ] 索引卡末尾登记了本次编译（REG-{next}）
