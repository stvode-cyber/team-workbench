## 推演 SOP（六步）

```
Step 1 正推
→ 照这个做法走下去，会发生什么？一条一条写
→ 覆盖：依赖链、边界条件、时间线、人员/算力需求
→ 禁止只推顺风局，必须写"如果 XX 点了会怎么样"

Step 2 反推
→ 假设这事已经失败了，往回找它是怎么死的
→ 5 Why 法：为什么失败 → 为什么那个问题 → 一直挖到根因
→ 失败模式清单：技术选型错 / 需求理解错 / 依赖没到位 / 性能崩 / 安全洞

Step 3 失败轨道
→ 必须覆盖至少 3 个炸点：
  ① 依赖点（某个库挂了 / API 改了 / 上游不动了）
  ② 边界点（极端输入 / 并发 / 大文件 / 低内存）
  ③ 随机第三个（最容易忽略的，比如部署脚本权限问题）
→ 每个炸点：炸了会怎么样 + 怎么发现 + 怎么回退

Step 4 竞品五张牌
→ 必须 5 个（含 1 个失败案例）
→ 每张：竞品名 + 做了啥 + 成没成 + star/commit 来源
→ 搜索关键词：`{行业} {功能} site:github.com` + `{功能} 失败 复盘`
→ 找不到 5 个也要如实说"只找到 X 个"，不许编造

Step 5 回滚点
→ 每个改动必须有"一键恢复原状"的路径
→ 代码：git commit 前的状态 / git revert
→ 数据：数据库备份 / 快照
→ 配置：旧配置文件存档
→ 如果回滚代价 > 重做代价，必须明确说出来

Step 6 结论
→ 方案 A/B/C 对比（风险最低 / 成本最低 / 效果最好）
→ 推荐哪个 + 为什么
→ GAP-xx 回流清单（推演时发现的未知点）
```

## 推演卡输出模板

```
═══ 推演卡 ═══
├─ 需求：{这次要推演什么}
├─ 方案对比：
│   ├─ A {保守方案}：风险 低/中/高 / 成本 低/中/高 / 效果 差/中/好
│   ├─ B {平衡方案}：...
│   └─ C {激进方案}：...
├─ 正推：{照这个做会发生什么}
├─ 反推：{假设失败，根因是什么}
├─ 失败轨道：
│   ├─ 炸点 1：... + 发现方式 + 回退路径
│   ├─ 炸点 2：...
│   └─ 炸点 3（随机）：...
├─ 竞品五张牌：
│   ├─ 1. {竞品名} + {star 数} + {做了啥} + {成没成}
│   ├─ ...（5 个）
│   └─ 来源：{URL}
├─ 回滚点：{每个改动的恢复路径}
├─ GAP-xx：{推演时发现的未知点，写回文件}
└─ 推荐：{选哪个 + 一句话理由}
```

## 必查表

| 场景 | 必须问 |
|---|---|
| 改代码 | 这行代码的上游调用者是谁？改了会不会崩？ |
| 花钱 | 这钱花了能拿到什么具体的、可验证的回报？ |
| 不可逆操作 | 有一键回滚吗？回滚代价多大？ |
| 新项目 | 竞品失败的那个，它为什么死的？我们能避开吗？ |
